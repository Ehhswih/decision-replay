# 设计说明

## 1. 术语

| 术语 | 含义 |
|---|---|
| 成交（Trade） | 导入的一笔买入或卖出：时间、代码、方向、价格、数量、费用，可选的“当时理由”和计划止损 / 目标 |
| 持仓段（Episode） | 同一只股票从空仓到有仓、再回到空仓的一段，是复盘的基本单位。一段里可以有多笔成交，每笔成交都是一个**决策点** |
| 决策时刻 t | 某笔成交的时间（北京时间，精确到分钟）。只有日期时按当天 09:30 处理，并标“时刻未知” |
| 证据（Evidence） | 复盘里能引用的每一条事实：一根 K 线、一份财报、一条新闻、一个程序算出的指标……每条都带来源、字段、单位、口径、事件时间、**可知时间**、抓取时间、数据状态 |
| 可知时间（available_at） | 这条信息最早什么时候能被投资者知道。时点切分只看它，不看事件时间 |
| 当时可知 / 事后才知 / 时序不确定 | 证据相对某个决策时刻的三种归类（规则见第 3 节） |
| 工作区（Workspace） | 不需要登录。每个访客用 cookie 里的随机 ID 隔离自己导入的数据，服务端只认自己生成的 UUID；示例组合是只读的公共工作区，cookie 伪造成 demo 也写不进去。清单另用一个访客 ID 保存，看示例组合的人也能存自己的清单 |

## 2. 数据模型

```
Trade        { id, rowNo, ts, timeKnown, code, name, side, price, qty, fee, reason?, planStop?, planTarget? }
Episode      { id, code, name, openTs, closeTs?, trades[], corpEvents[], buyCost, sellProceeds, dividends, fees,
               realizedPnl?, returnPct?, maxPosition }
Evidence     { id, kind, title, detail?, value?, unit?, caliber?, source, endpoint?, field?, url?,
               eventTime, availableAt, precision('ms'|'day'), nonPit?, status, thirdPartyAi?, fetchedAt,
               inputs[]?, tradeId?, tone?, important? }
BiasResult   { ruleId, name, scope, outcome('hit'|'not_hit'|'undetermined'), tradeId?, finding, rule,
               evidenceIds[], cost?, alternatives[], confidence }
Review       { episodeId, generatedAt, model, mode('ai'|'rules_only'), exAnte[], expost?, lessons[],
               biases[], attribution, dataUncertainties[], validationLog[], usage }
Claim        { text, type('fact'|'inference'|'uncertain'), confidence('high'|'mid'|'low'), evidenceIds[] }
ChecklistItem{ id, text, trigger, sourceEpisodeId?, sourceLessonId?, enabled, createdAt }
```

- `kind`：`price_bar` / `index_bar` / `financial` / `news` / `notice` / `anomaly` / `hot_rank` / `dragon_tiger` / `industry` / `corporate_action` / `computed`
- `computed` 是程序算出来的指标（例如“买入前 5 日涨幅”），`inputs` 列出它用到的证据，`caliber` 里写公式。这样页面上每个数字都能一路点回原始字段。
- `status`：`ok` 正常 / `partial` 部分缺失 / `stale` 过期 / `missing` 缺失 / `failed` 获取失败 / `conflict` 冲突

## 3. 时点切分规则

所有时间都按 **Asia/Shanghai** 处理，不依赖本机或服务器的时区（开发机就是 UTC-4）。

| 证据 | 可知时间 | 精度 |
|---|---|---|
| 个股 / 指数第 D 日日 K | D 日 15:00 | 毫秒 |
| 财报 | `report_date_ms`（披露日，北京时间 0 点） | 天 |
| 扶摇个股新闻 | `publish_time_ms` | 毫秒 |
| 扶摇异动解读 | `first_publish_time` | 毫秒 |
| iFinD 新闻 / 公告 | 返回里的“日期” | 天 |
| 热股排名（第 D 日） | D+1 日 0 点（保守处理） | 毫秒 |
| 龙虎榜（第 D 日） | D+1 日 0 点（保守处理） | 毫秒 |
| 除权除息 | 除权日 | 天 |
| 行业归属 | 只有当前数据 | 非时点，一律“时序不确定” |
| 程序算出的指标 | 所用输入里最晚的可知时间 | 跟随输入 |

对决策时刻 t 的归类：
- 精度到毫秒：`availableAt <= t` 算当时可知，否则算事后才知；
- 精度到天：比 t 早一天及以上算当时可知；和 t 同一天算**时序不确定**；比 t 晚算事后才知；
- 时刻未知的成交按 09:30 处理。这样只会少算“当时可知”的信息，不会多算，宁可漏掉也不泄漏。

**iFinD 的时间范围不是硬过滤**（实测会返回窗口外的文章），所以拿回来的每一条都要按上面的规则重新归类。

**“回到当时”不透露之后的事**：除了遮住决策之后的 K 线和证据，K 线横轴只给幕布留固定 10 个交易日（不随实际持有时长变化），清仓日期、之后决策点的日期和类型、事后证据的条数都不显示。否则从幕布宽度就能看出拿了多久，从“加仓”标签能猜到之后跌了。

## 4. 成交导入和校验

导入时先清洗：
- 编码按 UTF-8 严格解码，失败再按 GBK；表头前的标题行跳过（在前 10 行里找同时有代码列和买卖列的一行）；
- 代码去掉 `="…"`、`'` 和 `.0`，Excel 吃掉前导 0 的补齐到 6 位；时间支持 `10:31:22`、`103122`、`93122`；
- 不是股票买卖的记录跳过并汇总说明：按操作类型（银证转账、股息红利、申购配号、回购、质押、理财……）和品种（逆回购 204/131、ETF 和基金、债券和可转债、B 股、申购代码）；成交数量为 0 的行也跳过；
- 同一委托的分笔成交合并：有合同编号按编号，没有时按同一只、同方向、同一分钟；数量相加、价格按成交量加权、费用相加；
- 没有计划列时，从备注里读“止损8%”“目标+15%”。

然后校验：

- 必须是交易日（扶摇交易日历）
- 成交价必须在当天不复权日 K 的最低价和最高价之间，否则标 `conflict`：“成交价与当日行情不符，可能是录入错误或复权口径不同”
- 买入数量是 100 股的整数倍（科创板 200 股起，之后按 1 股递增）；卖出数量不能超过当时持仓
- 持仓段内遇到除权除息（例如 300502 新易盛 2026-06-11 每股派 1 元、送转 0.4 股，不复权日 K 单日“下跌” 31.9%），收益按复权口径计算，并在时间线上标出除权事件，不能把它当成暴跌

## 5. 行为偏差规则

规则命中是**事实**，“这是一种偏差”是**推断**，每条都附上其他可能的解释。数据不够时输出“无法判定”，不能输出“未命中”。

| 编号 | 偏差 | 判定规则（默认阈值） | 层面 |
|---|---|---|---|
| B1 | 追涨 | 买入前 5 个交易日涨幅 ≥ 15%，或买入价创近 20 日收盘新高且 5 日涨幅 ≥ 8%（只看“接近高点”会把横盘甚至下跌中的买入也算进去） | 单笔 |
| B2 | 追热点 | 买入前一个交易日热股排名进前 20，或前 3 个交易日上过龙虎榜 | 单笔 |
| B3 | 恐慌卖出 | 卖出前 3 个交易日跌幅 ≥ 10%。卖出后的走势是事后信息，只用来显示“代价”，不参与判定 | 单笔 |
| B4 | 处置效应 | 亏损段平均持有天数 ≥ 盈利段的 1.5 倍（至少 4 段已平仓，盈亏各至少 1 段） | 组合 |
| B5 | 过度交易 | 同一只股票 10 个交易日内买卖 ≥ 3 次。交易日来自行情，行情缺失、交易日盖不住成交日期时判“无法判定” | 组合 |
| B6 | 锚定成本价 | 持仓中最大浮亏 ≥ 15%，之后在成本价 ±2% 以内卖出 | 单段 |
| B7 | 偏离计划 | 写了止损 / 目标时，持有过程和最后的退出分开核对：① 收盘跌破止损线后超过 1 个交易日才卖；② 目标达到后没卖，卖出时比目标少 3 个百分点以上；③ 没到目标就卖、少赚 3 个百分点以上。①② 即使最后回本也算偏离。跌破后下一个交易日就卖、但因跳空多亏的，不算没执行。缺少持仓期间的行情时只能用最后的卖出价兜底，判不了就是“无法判定”。没发现偏离只说明规则没查到问题，置信度记为“中”。止损和目标按写下的时间生效：每笔卖出只对照它之前最近一次写下的计划，止损线也只从写下它的那笔买入之后开始核对；买入当天的收盘也算 | 单段 |
| B8 | 选择性关注 | 决策前 10 天内有当时可知的重要负面信息（公告、异动解读、标题含业绩/减持/风险等的新闻），而且直接动摇买入逻辑，理由里却没有提到。规则先列出候选（10 天内、当时可知、语气负面的新闻、公告、异动），全部放进当时视角的证据包，由 AI 逐条核对是否提到、是否相关；AI 自己带进来的其他证据（比如标题正面的新闻）不算，AI 自己说无法判断的不算，候选没核对完时不判未命中。置信度最高为“中”，只有为“中”时才影响问题归类 | 单笔 |

## 6. 归因

- **收益拆解**：持有期收益 = 市场（沪深 300）+ 行业超额（行业指数 − 沪深 300）+ 个股特异（个股 − 行业指数），三部分相加等于个股收益。行业指数用当前归属，标“非时点”。
- **过程和结果**：过程好不好（理由是否基于当时可知的证据、有没有计划、有没有按计划执行）× 结果好不好（收益正负），做成 2×2 格子。
- **问题归类**，按顺序判断：
  1. 没做好：有计划但没按计划执行（B7 命中）；
  2. 看错了，而且相反的证据当时就能看到：满足第 4 条，并且至少一条相反证据在买入时已经可知。这不是事后才出现的意外，所以排在第 3 条前面；
  3. 可能受事后事件影响：过程没有明显问题、亏损，持仓期间出现了买入时还不知道的重要利空，而且 AI 没有核对出被忽略的当时可知负面信息。措辞是“可能与亏损有关，不能证明是主因”；
  4. 看错了：AI 写出了理由里被推翻的假设，并引用了和它相反的新闻、公告、异动或财报证据（通过引用校验）。只引用成交记录或价格涨跌的不算，那等于“因为亏了所以看错了”；
  5. 暂无法归类：以上都不满足的亏损。持仓期间出现过的利空作为“可能相关的影响因素”列出，不据此下结论；
  6. 没有明显问题：盈利。过程有明显问题时提醒“结果好不代表方法对”。

## 7. AI 的角色

| AI 做 | AI 不做 |
|---|---|
| 逐条核对理由里的说法（有证据支持 / 和证据矛盾 / 无法核实），找出理由没提到、和买入逻辑相关的负面信息 | 算任何数字 |
| 用证据写“当时视角”和“事后复盘”的叙述 | 判定规则是否命中（B8 只提供核对结果，由程序按规则定论） |
| 给偏差写“其他可能的解释” | 预测涨跌、给买卖或仓位建议 |
| 把教训改写成清单条目，在决策前检查时找出相关教训 | 引用证据包以外的信息 |

**防后见之明：**
1. “当时视角”和“事后复盘”分两次调用，第一次只给当时可知的证据；
2. 当时视角做匿名化：股票名和代码换成“标的A”，日期换成相对日期（D-3），年份换成相对决策当年的 Y-1，证据 id 换成 E1、E2 这样的临时编号（原 id 里有代码和报告期），模型输出的编号再换回真实 id，不让模型凭记忆知道后来发生了什么；
3. 引用校验：每条结论必须带 `evidenceIds`；当时视角里引用的证据，可知时间必须早于 t，不满足的整条丢掉并写进 `validationLog`；
4. 数字校验：结论里出现的数字必须能在引用的证据、这次决策的成交记录或程序算出的规则结果里找到，找不到的整条丢掉；叙述按句核对，对不上的句子删掉；
5. 后见之明泄漏检测：当时视角的输出里出现了输入证据包里没有的事后事件关键词，就记进 `validationLog`；
6. 合规过滤（第 8 节）；
7. 模型返回格式错误、空输出或网络错误时先重试一次，仍失败就只展示规则版复盘，页面顶部提示原因。

模型：`deepseek-flash`（OpenAI 兼容接口，JSON 输出）。

## 8. 合规

- 拦截的说法：建议买入 / 卖出 / 加仓 / 减仓 / 清仓 / 持有、目标价、必涨、必跌、稳赚、保本、翻倍、仓位 X 成、满仓、梭哈，以及对未来涨跌的判断（“将会上涨”“预计下跌”等）。命中的句子整句替换成提示语，并记录下来。
- 决策前检查页只列历史教训、清单和当前的事实，不回答“能不能买”。用户问到这类问题时，回固定说明。
- 每页底部写明：本产品用于复盘学习，不构成投资建议。
- 交易数据只用构造的示例或用户自己上传的匿名数据；API Key 只在服务端环境变量里。
- 用户导入的成交在服务器上保留 7 天后自动删除，也可以随时一键删除；示例组合对访客只读。
- 决策前检查和复盘生成按访客 IP 限流，防止公开地址被刷光数据源和模型额度。

## 9. 数据状态和降级

- 每个数据源的每次调用都记录：接口、参数、结果码、耗时、抓取时间。
- 关键数据（K 线）缺失时，不做收益归因和价格类规则，直接说明原因；非关键数据（新闻、热榜）缺失时继续，但在“不确定因素”里列出来。
- 空列表不等于“没有”：扶摇文档明确说异动解读的空列表可能是服务降级，所以显示“未获取到”，不显示“无异动”。
- iFinD 有调用计数，免费额度快用完时只用扶摇，并在数据状态页说明。额度是累计总量，所以清理 30 天前的调用日志时，iFinD 的实际调用记录保留。
- 除权除息没取到时，持仓段标记“可能漏了分红送转”：导入校验里给出提醒，收益旁边标注，证据集的数据源状态记为失败、不长期缓存，收益拆解标为部分可用。
- iFinD 熔断：连续 2 次网络失败后暂停调用 10 分钟，这期间直接返回“获取失败”（照样记入数据源状态、证据集不长期缓存），不让几十个持仓段各自等超时。
- 扶摇对没有除权除息记录的股票返回报错“No adjustment events”，按“没有除权”处理，不算失败。
- 缓存：历史数据（已收盘的日 K、财报、已发布的新闻）不会再变，缓存后长期使用；页面上显示“数据抓取于某时”。
- 证据集缓存：只有持仓已结束、观察窗口已过、新闻翻到了决策前、没有数据源失败或用旧缓存时，才长期缓存；否则 30 分钟后重新整理。重新生成复盘时，这个持仓段的证据强制重新取数。
- “没找到”不等于“没有”：决策前检查里，热股排名或任何一天的龙虎榜没取到、又没有命中，热度检查显示“无法判断”；异动、新闻、公告任何一项没取到、又没找到负面信息，负面信息检查显示“无法判断”。复盘里的选择性关注（B8）同理。只有数据取全、确实没命中时才显示“未触发”。不适用的检查（买入时的恐慌卖出）显示“不适用”。

## 10. 用户自己留下的记录

- **揭晓前的判断**：在“回到当时”视角的底部，用户先选理由是否充分（充分 / 有缺口 / 不充分），可选写下当时最该担心什么，再揭晓。每笔成交只能写一次，写下后不能修改；如果写之前已经打开过这个持仓段的揭晓视图，记录上标注“揭晓后才写”。揭晓后顶部并排显示：左边是用户的判断，右边是整段的过程与结果、这笔成交命中的规则、AI 对理由的核对、后来出现的负面事件。只摆事实对照，不给用户的判断打分。
- **决策记录**：决策前检查的结果可以存为决策记录，保存时的理由、计划、检查结果和事实原样留档。补充理由时新增一个版本，原来的版本不动。导入成交后，同一只股票、同方向、成交前 7 天内保存的记录会出现在“回到当时”里：成交之前写的版本算当时的理由，之后补充的版本标注“成交后补充”，揭晓后才显示。
- 两者都按浏览器 cookie 区分（看示例组合的访客也能留），保留 180 天，可以一键删除；删除导入数据时，这个工作区下的判断一起删除。
