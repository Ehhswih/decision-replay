# 决策回放：投资决策复盘与学习

同花顺 AI 题「题目 11｜投资决策复盘与学习」（三选一）。

- **在线地址**：<http://49.234.35.196>（腾讯云上海轻量服务器，按 IP 访问，所以是 HTTP）
- **源代码**：<https://github.com/Ehhswih/decision-replay>
- 打开即是示例组合，不需要登录；也可以导入自己的交割单，或者先下载一份接近真实的示例交割单试着导入

投资者复盘时最常见的问题，是拿后来才知道的事去评价当时的决定。决策回放把成交、当时写下的理由、行情、财报、公告和新闻对齐到一条时间线上，**先只给你看下单前已经公开的信息，等你写下自己的判断，再揭晓后来发生了什么**。行为偏差由程序按规则判定，AI 只负责解读和措辞，每条结论都能点回原始字段。认可的教训可以加入清单，下次下单前在「决策前检查」里逐条对照。

## 三分钟体验路径

1. 首页点「看示例组合」：一位虚构投资者 2026 年 6–9 月的 21 笔成交（股票和行情是真实的，成交是构造的，见 [demo/README.md](demo/README.md)）。
2. 在「我的决策」里打开**兆易创新**。默认是「回到当时」：K 线只画下单前已经收盘的部分（不复权价格，纵轴也只按这部分定），收益遮住。看下单时理由里写了什么、当时已经能看到哪些风险（公司在 6 月 30 日已经公告股价偏离风险）、理由逐条核对的结果。顶部的决策点可以切到下一笔；在“回到当时”里，之后的决策点只显示序号，不透露日期，也不透露是加仓还是卖出。
3. 切到第 3 个决策点（**07-20 卖出**）：幕布停在卖出那一刻，能看到卖前 3 天已跌 25.7%、8% 的止损线早在 7 月 6 日就被跌破；第二天的涨停被遮住。
4. 在页面底部先写下你的判断：理由是否充分、当时最该担心什么（写下后不能改）。点「保存，然后揭晓」：顶部是揭晓前后对照，下面是过程 × 结果格子、问题归类（没做好：止损线 7 月 6 日被跌破后，又过了 10 个交易日才卖）、复盘叙述、行为偏差和另一种可能的解释、不确定因素。点任何一个证据标签，看它的来源接口、字段、口径和可知时间。
5. 对比**赛力斯**、**宁德时代**和**新易盛**。赛力斯写了止损也按计划执行了，但买入前 4 天已有“6 月销量同比承压”的研报，理由里没提，之后半年报预亏，所以归为“看错了”，并列出被推翻的假设和证据。宁德时代同样亏损，但找不到理由里哪条假设被事件或基本面推翻，归为“暂无法归类”。新易盛持有期间 10 送 4，不复权价格从 780 到 580，实际是赚的。
6. 回到「我的决策」看这一组决策的总结（胜率、盈亏段的平均收益和持有天数、问题归类和偏差分布）和跨持仓段的模式（处置效应、过度交易）。
7. 在「下次可以做什么」里把一条教训加入清单，然后去「决策前检查」输入任意一只股票，看清单逐条套到它现在的数据上。检查完可以存为决策记录；之后补充理由会新增一个版本，原来写的保留。
8. 「数据状态」页能看到每一次外部调用的结果、缓存情况和 iFinD 额度。
9. 想看真实交割单导入后的样子：首页点「下载一份示例交割单」，再点「导入我的成交 CSV」选这个文件。这是一位模拟散户 7 个月的同花顺格式交割单，价格都来自真实行情，夹着银证转账、新股申购、逆回购、ETF 和分笔成交；导入后整理出 29 个持仓段，「我的决策」的持仓时间轴上能看到哪些持仓重叠、哪只股票来回做了很多次。

## 目标用户与产品选择

**用户**：交易几只 A 股的个人投资者。会记录买卖，偶尔写几句理由，但复盘时只记得赚了还是亏了。

**核心任务**：选一段历史持仓，看清“当时我知道什么、怎么想的、后来发生了什么”，得出能用在下一次的教训。

**为什么这样做**：

- **按持仓段复盘**，而不是按单笔成交。一段持仓从买入到清仓，中间的加仓、止损、卖出都是这次决策的一部分；每一笔成交都可以单独“回到当时”，卖出也一样。
- **一次和一组都能看**：单个持仓段看细节，决策列表上方汇总这一组决策的胜负、盈亏段的收益和持有时间、问题归类和偏差分布。
- **“回到当时”是默认视角**。先遮住结果，用户和模型都只能看到下单前的信息，这是避免后见之明最直接的办法。
- **揭晓前先留下自己的判断**。看完当时的信息，先写下理由是否充分、最该担心什么，再和规则、AI 的结论并排对照。复盘练的是用户自己的判断，不只是读 AI 的结论。
- **规则判定，AI 解读**。追涨、偏离计划这类判断用程序按阈值算，结论稳定、可复现、能追溯；AI 负责把证据讲清楚、核对理由、提炼教训，它的输出必须过引用、数字、时点和合规四道校验。
- **教训落到清单，清单落到下一次决策**。复盘的价值在下一笔交易，所以清单条目带类型（追涨、追热点、执行计划……），能在决策前检查里自动核对数据。
- **不做预测和建议**。决策前检查只告诉你哪条检查被触发、依据是什么；问“能不能买”会得到固定说明。

## 核心设计

详见 [docs/design.md](docs/design.md)。要点：

**时点切分**：每条证据都有“可知时间”，和决策时刻比较后分成当时可知 / 事后才知 / 时序不确定。

| 证据 | 可知时间 |
|---|---|
| 第 D 日日 K | D 日 15:00（盘中成交时，当天 K 线算事后） |
| 财报 | 披露日，只精确到天，同一天算时序不确定 |
| 新闻、异动解读 | 发布时间（毫秒） |
| 热股排名、龙虎榜 | 第二天 0 点（收盘后才发布，保守处理） |
| 行业归属 | 只有当前数据，一律时序不确定 |
| 只有日期的成交 | 按 09:30 处理：只会少算当时可知的信息，不会多算 |

所有时间按 Asia/Shanghai 计算，不依赖服务器时区（单测在两个时区下各跑一遍）。

“回到当时”也不透露之后发生了什么：K 线横轴只给幕布留固定的 10 个交易日，清仓日期、之后决策点的日期和类型、事后证据的条数都先不显示，免得从幕布宽度或标签推出拿了多久、有没有加仓。

**行为偏差规则**（B1–B8）：追涨、追热点、恐慌卖出、处置效应、过度交易、锚定成本价、偏离计划、选择性关注。规则命中是事实，“这是偏差”是推断，每条附上其他可能的解释；数据不够时输出“无法判定”，不会冒充“未命中”；卖出后的走势只作为“事后代价”展示，不参与判定。偏离计划把持有过程和最后的退出分开看：收盘跌破止损线后超过 1 个交易日才卖、达到目标后又回吐，即使最后回本也算偏离；没发现偏离只说明规则没查到问题，不等于证明执行到位。

**归因**：过程好坏 × 结果好坏的 2×2；问题归类为看错了 / 没做好 / 可能受事后事件影响 / 暂无法归类 / 没有明显问题。亏损本身不能证明判断错了：只有找到理由里被推翻的假设，以及和它相反的新闻、公告、异动或财报证据，才归为看错了；只拿价格下跌当证据不算。相反的证据买入时就能看到的，直接归为看错了，不算事后意外。证据不够时写“暂无法归类”，持仓期间出现的利空只写成“可能相关的影响因素”。持有期收益拆成市场、行业超额、个股特异三部分。

**持仓计算**：成交价必须落在当天不复权最高价和最低价之间；持有期间的送转和分红计入持仓；止损、收益按前复权口径计算，平均成本用复权价和复权股数算，送转后再加减仓也不会算错。止损和目标按写下的时间生效：后来加仓时才写的止损，不拿去评价之前的卖出。除权除息数据没取到时，收益旁边标“可能漏了分红送转”。

**导入**：识别同花顺、东方财富等券商交割单的常见列名和写法，包括 GBK 编码、表头前的标题行、`="002594"` 这样的代码、丢了前导 0 的时间（`93122`）和负数的卖出数量。银证转账、股息红利、新股申购和配号、逆回购、ETF、可转债这些不是股票买卖的记录直接跳过，并说明跳过了哪几行；同一委托的分笔成交合并成一笔（按成交量加权均价，费用相加）；没有计划列时，从备注里读“止损8%”“目标+15%”。

**界面**：颜色只留给“当时 / 事后”（靛蓝 / 琥珀）和涨跌。产品标志、首页演示和 K 线上的幕布用的是同一条“决策时刻”切线：左边是当时，右边是还没揭晓的事后。「我的决策」上方是一条指标带和问题分布，下面的持仓时间轴把所有持仓段放在同一条时间轴上。支持深色模式（默认跟随系统，右上角可以切换），手机上也能用。

## AI 的角色

| AI 做 | AI 不做 |
|---|---|
| 写“当时视角”：当时支持理由的证据、已经存在的风险、逐条核对理由、找出理由没提到的相关负面信息 | 算任何数字（全部由程序计算并作为证据提供） |
| 写“事后复盘”：叙述、事实归因、解释命中的规则、哪条假设没成立、不确定因素 | 判定规则是否命中（只在“选择性关注”上提供核对结果，且作为提示） |
| 把教训写成下次可以执行的检查动作 | 预测涨跌、给买卖或仓位建议 |

模型：DeepSeek `deepseek-flash`（OpenAI 兼容接口，JSON 输出）。

**防后见之明**：当时视角和事后复盘分两次调用，当时视角只给决策时可知的证据，并把股票名、代码换成“标的A”，日期换成“D-3”这样的相对日期，年份换成“Y-1”，证据编号换成 E1、E2 这样的临时编号（原来的编号里带着代码和报告期）。

**输出校验**（不合格的整条丢掉，界面上“AI 输出校验”里能看到丢了什么、为什么）：

1. 每条结论必须引用证据包里真实存在的证据；
2. 当时视角引用的证据，可知时间必须早于决策时刻；
3. 结论里的数字必须能在引用的证据里找到（叙述按句核对，对不上的句子删掉）；
4. 合规过滤：买卖建议、目标价、仓位、收益承诺、涨跌预测整句替换；
5. 后见之明泄漏检测：输出里出现了输入证据包里没有的事后事件关键词就记录下来。

模型调用失败时降级为规则版复盘，页面写明原因。开发过程中 AI 出过哪些错、怎么发现和修正的，见 [docs/ai-usage.md](docs/ai-usage.md)。

## 数据来源

| 来源 | 用了什么 |
|---|---|
| 扶摇金融数据 API | 个股日 K（不复权 / 前复权）、指数日 K、交易日历、除权除息、利润表（含披露日）、行业归属、个股新闻、日期范围异动解读、热股排名、龙虎榜、标的检索 |
| iFinD MCP | 公告检索（`search_notice`）。新闻检索实测返回结果全部落在请求的时间窗口外，没有采用 |
| DeepSeek | 复盘文字生成 |

每条证据都记录了来源接口、字段、单位、口径、事件时间、可知时间、抓取时间和数据状态；每一次外部调用写入调用日志（「数据状态」页可见）。历史数据缓存在 SQLite 里，已收盘的数据永久缓存。接口实测记录见 [docs/data-probe.md](docs/data-probe.md)。

**用户数据**：导入的成交只用于本人的复盘，按浏览器 cookie 区分，不需要登录；在服务器上保留 7 天后自动删除，也可以随时在首页或「我的决策」里一键删除。揭晓前写下的判断和决策记录同样按浏览器区分，保留 180 天，可以在「决策前检查」页一键删除。示例组合是构造的匿名数据。

**数据异常时的处理**：K 线等关键数据失败时不计算相关指标、规则输出“无法判定”；本次失败但有旧缓存时用旧数据并标“用了缓存”；空列表不等于“没有”（异动解读为空时显示“未获取到”）；iFinD 有调用计数（累计用量的记录不随日志清理删除），接近免费额度上限时只用扶摇；所有异常都列在复盘的“不确定因素”里。决策前检查和“选择性关注”规则也一样：龙虎榜、新闻、公告任何一项没取到，又没有找到命中的证据，就显示“无法判断”，不显示“未触发”。证据集只有在持仓已结束、观察窗口已过、数据源全部正常时才长期缓存，否则 30 分钟后重新取数；持仓段本身变了（例如除权数据恢复后收益重算）也会重建；重新生成复盘时强制重新取数。iFinD 连续 2 次连接失败后暂停调用 10 分钟，这期间的持仓段照样标“公告未取到”，一个组合几十个持仓段不会被超时拖住；扶摇对没有除权记录的股票会返回报错，按“没有除权”处理，不算获取失败。

## 已知边界

- **数据**：估值只有最新快照，没有当时的 PE；主力资金历史只在同花顺 AI 客户端内开放，没有用；行业归属只有当前值；个股新闻只能从最新往前翻页（热门股约 5 个月），更早的新闻可能不全；扶摇对旧报告期给的披露日有时是重述日期，按法定期限过滤掉了；异动解读是同花顺 AI 生成的摘要，界面上已标注。
- **时点**：财报、iFinD 公告只精确到天，和决策同一天的只能标“时序不确定”。
- **规则**：阈值是经验值（例如 5 日涨幅 15%），可以讨论。“选择性关注”要靠 AI 判断负面信息和买入逻辑是否相关，在示例组合上仍有主观性，所以只作为提示：AI 只能核对规则列出的负面信息，自己带进来的不算；置信度最高为“中”，也只有置信度为“中”时才影响问题归类。
- **AI**：数字核对允许四舍五入误差（例如 41.67 写成 41.7），所以和真实值极接近的错误数字拦不住。泄漏对照实验里，两个案例无论匿名与否都没有出现泄漏，可能是因为事件晚于模型的训练数据。所以在这组样本上，匿名化的效果无法证明，它只是一道防线。
- **复权**：除权日按 0 点处理，送转股向下取整，分红按税前计。
- **部署**：单实例 + SQLite，限流和缓存都在进程内；访问用 HTTP（国内服务器没有备案域名）。

## 本地运行

需要 Node.js 24 及以上（用到内置的 `node:sqlite`）。

```bash
npm install
cp .env.example .env.local   # 填入扶摇、DeepSeek、iFinD 的 Key
npm run dev                  # http://localhost:3000
```

| 环境变量 | 说明 |
|---|---|
| `FUYAO_API_KEY` | 扶摇金融数据 API Key |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | DeepSeek，模型默认 `deepseek-flash` |
| `IFIND_MCP_URL` / `IFIND_MCP_AUTH` | iFinD MCP 综合服务的地址和 Authorization |
| `IFIND_QUOTA_LIMIT` | iFinD 调用上限（免费试用总共 2000 次），到了就只用扶摇 |
| `ADMIN_TOKEN` | 运维令牌，带上才能重新生成示例组合的复盘 |
| `DATA_DIR` | SQLite 数据目录，默认 `./data` |

## 部署

```bash
bash scripts/deploy.sh ubuntu@<服务器IP> :80 -i <私钥路径>
ADMIN_TOKEN=<与服务端一致> bash scripts/pregenerate.sh http://<服务器IP>   # 预热示例组合并生成复盘
node scripts/smoke.mjs http://<服务器IP>
```

Docker 多阶段构建 + Caddy 反向代理（填域名时自动 HTTPS）。部署脚本会在国内服务器上配置 Docker 和 npm 镜像源。
