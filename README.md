# 决策回放：投资决策复盘与学习

同花顺 AI 题第 2 题「投资决策复盘与学习」。

- **在线地址**：<http://49.234.35.196>（腾讯云上海轻量服务器，按 IP 访问，所以是 HTTP）
- 打开即是示例组合，不需要登录；也可以导入自己的成交 CSV

投资者复盘时最常见的问题，是拿后来才知道的事去评价当时的决定。决策回放把成交、当时写下的理由、行情、财报、公告和新闻对齐到一条时间线上，**先只给你看下单前已经公开的信息，再揭晓后来发生了什么**；行为偏差由程序按规则判定，AI 只负责解读和措辞，每条结论都能点回原始字段；最后把认可的教训加入清单，下次下单前在「决策前检查」里逐条对照。

## 三分钟体验路径

1. 首页点「看示例组合」：一位虚构投资者 2026 年 6–9 月的 21 笔成交（股票和行情是真实的，成交是构造的，见 [demo/README.md](demo/README.md)）。
2. 在「我的决策」里打开**兆易创新**。默认是「回到当时」：K 线上决策日之后被幕布遮住，收益也遮住。看下单时理由里写了什么、当时已经能看到哪些风险（公司在 6 月 30 日已经公告股价偏离风险）、理由逐条核对的结果。顶部可以切到第二个决策点（7 月 1 日加仓）。
3. 把决策点切到 **07-20 卖出**：幕布停在卖出那一刻，能看到卖前 3 天已跌 25.7%、8% 的止损线早在 7 月 6 日就被跌破；第二天的涨停被遮住。
4. 点「揭晓结果」：过程 × 结果格子、问题归类（没做好：止损 8% 没执行，多亏 33.6 个百分点）、复盘叙述、行为偏差和另一种可能的解释、不确定因素。点任何一个证据标签，看它的来源接口、字段、口径和可知时间。
5. 对比**赛力斯**（过程合理、按计划止损，亏损来自买入后才公布的业绩预亏）和**新易盛**（持有期间 10 送 4，不复权价格从 780 到 580，实际是赚的）。
6. 回到「我的决策」看这一组决策的总结（胜率、盈亏段的平均收益和持有天数、问题归类和偏差分布）和跨持仓段的模式（处置效应、过度交易）。
7. 在「下次可以做什么」里把一条教训加入清单，然后去「决策前检查」输入任意一只股票，看清单逐条套到它现在的数据上。
8. 「数据状态」页能看到每一次外部调用的结果、缓存情况和 iFinD 额度。

## 目标用户与产品选择

**用户**：交易几只 A 股的个人投资者。会记录买卖，偶尔写几句理由，但复盘时只记得赚了还是亏了。

**核心任务**：选一段历史持仓，看清"当时我知道什么、怎么想的、后来发生了什么"，得出能用在下一次的教训。

**为什么这样做**：

- **按持仓段复盘**，而不是按单笔成交。一段持仓从买入到清仓，中间的加仓、止损、卖出都是这次决策的一部分；每一笔成交都可以单独"回到当时"，卖出也一样。
- **一次和一组都能看**：单个持仓段看细节，决策列表上方汇总这一组决策的胜负、盈亏段的收益和持有时间、问题归类和偏差分布。
- **"回到当时"是默认视角**。先遮住结果，用户和模型都只能看到下单前的信息，这是避免后见之明最直接的办法。
- **规则判定，AI 解读**。追涨、偏离计划这类判断用程序按阈值算，结论稳定、可复现、能追溯；AI 负责把证据讲清楚、核对理由、提炼教训，它的输出必须过引用、数字、时点和合规四道校验。
- **教训落到清单，清单落到下一次决策**。复盘的价值在下一笔交易，所以清单条目带类型（追涨、追热点、执行计划……），能在决策前检查里自动核对数据。
- **不做预测和建议**。决策前检查只告诉你哪条检查被触发、依据是什么；问"能不能买"会得到固定说明。

## 核心设计

详见 [docs/design.md](docs/design.md)。要点：

**时点切分**：每条证据都有"可知时间"，和决策时刻比较后分成当时可知 / 事后才知 / 时序不确定。

| 证据 | 可知时间 |
|---|---|
| 第 D 日日 K | D 日 15:00（盘中成交时，当天 K 线算事后） |
| 财报 | 披露日，只精确到天，同一天算时序不确定 |
| 新闻、异动解读 | 发布时间（毫秒） |
| 热股排名、龙虎榜 | 第二天 0 点（收盘后才发布，保守处理） |
| 行业归属 | 只有当前数据，一律时序不确定 |
| 只有日期的成交 | 按 09:30 处理：只会少算当时可知的信息，不会多算 |

所有时间按 Asia/Shanghai 计算，不依赖服务器时区（单测在两个时区下各跑一遍）。

**行为偏差规则**（B1–B8）：追涨、追热点、恐慌卖出、处置效应、过度交易、锚定成本价、偏离计划、选择性关注。规则命中是事实，"这是偏差"是推断，每条附上其他可能的解释；数据不够时输出"无法判定"，不会冒充"未命中"；卖出后的走势只作为"事后代价"展示，不参与判定。

**归因**：过程好坏 × 结果好坏的 2×2；问题归类为看错了 / 没做好 / 不可预见 / 没有明显问题；持有期收益拆成市场、行业超额、个股特异三部分。

**持仓计算**：成交价必须落在当天不复权最高价和最低价之间；持有期间的送转和分红计入持仓；止损、收益按前复权口径计算。

## AI 的角色

| AI 做 | AI 不做 |
|---|---|
| 写"当时视角"：当时支持理由的证据、已经存在的风险、逐条核对理由、找出理由没提到的相关负面信息 | 算任何数字（全部由程序计算并作为证据提供） |
| 写"事后复盘"：叙述、事实归因、解释命中的规则、哪条假设没成立、不确定因素 | 判定规则是否命中（只在"选择性关注"上提供核对结果，且作为提示） |
| 把教训写成下次可以执行的检查动作 | 预测涨跌、给买卖或仓位建议 |

模型：DeepSeek `deepseek-flash`（OpenAI 兼容接口，JSON 输出）。

**防后见之明**：当时视角和事后复盘分两次调用，当时视角只给决策时可知的证据，并把股票名、代码换成"标的A"、日期换成"D-3"这样的相对日期。

**输出校验**（不合格的整条丢掉，界面上"AI 输出校验"里能看到丢了什么、为什么）：

1. 每条结论必须引用证据包里真实存在的证据；
2. 当时视角引用的证据，可知时间必须早于决策时刻；
3. 结论里的数字必须能在引用的证据里找到（叙述按句核对，对不上的句子删掉）；
4. 合规过滤：买卖建议、目标价、仓位、收益承诺、涨跌预测整句替换；
5. 后见之明泄漏检测：输出里出现了输入证据包里没有的事后事件关键词就记录下来。

模型调用失败时降级为规则版复盘，页面写明原因。开发过程中 AI 出过哪些错、怎么发现和修正的，见 [docs/ai-usage.md](docs/ai-usage.md)。

## 数据来源

| 来源 | 用了什么 |
|---|---|
| 扶摇金融数据 API | 个股日 K（不复权 / 前复权）、指数日 K、交易日历、除权除息、利润表（含披露日）、行业归属、个股新闻、日期范围异动解读、热股排名、龙虎榜、标的检索 |
| iFinD MCP | 公告检索（`search_notice`）。新闻检索实测返回结果全部落在请求的时间窗口外，没有采用 |
| DeepSeek | 复盘文字生成 |

每条证据都记录了来源接口、字段、单位、口径、事件时间、可知时间、抓取时间和数据状态；每一次外部调用写入调用日志（「数据状态」页可见）。历史数据缓存在 SQLite 里，已收盘的数据永久缓存。接口实测记录见 [docs/data-probe.md](docs/data-probe.md)。

**用户数据**：导入的成交只用于本人的复盘，按浏览器 cookie 区分，不需要登录；在服务器上保留 7 天后自动删除，也可以随时在首页或「我的决策」里一键删除。示例组合是构造的匿名数据。

**数据异常时的处理**：K 线等关键数据失败时不计算相关指标、规则输出"无法判定"；本次失败但有旧缓存时用旧数据并标"用了缓存"；空列表不等于"没有"（异动解读为空时显示"未获取到"）；iFinD 有调用计数，接近免费额度上限时只用扶摇；所有异常都列在复盘的"不确定因素"里。

## 已知边界

- **数据**：估值只有最新快照，没有当时的 PE；主力资金历史只在同花顺 AI 客户端内开放，没有用；行业归属只有当前值；个股新闻只能从最新往前翻页（热门股约 5 个月），更早的新闻可能不全；扶摇对旧报告期给的披露日有时是重述日期，按法定期限过滤掉了；异动解读是同花顺 AI 生成的摘要，界面上已标注。
- **时点**：财报、iFinD 公告只精确到天，和决策同一天的只能标"时序不确定"。
- **规则**：阈值是经验值（例如 5 日涨幅 15%），可以讨论；"选择性关注"依赖 AI 判断负面信息是否和买入逻辑相关，示例组合上仍有主观性，所以只作为提示，置信度最高为"中"，只有置信度为"中"时才影响归类。
- **AI**：数字核对允许四舍五入误差（例如 41.67 写成 41.7），所以和真实值极接近的错误数字拦不住；泄漏对照实验中两个案例匿名与否都没有出现泄漏，可能因为事件晚于模型训练数据，匿名化的效果在这组样本上无法证明，只是一道防线。
- **复权**：除权日按 0 点处理，送转股向下取整，分红按税前计。
- **部署**：单实例 + SQLite，限流和缓存都在进程内；访问用 HTTP（国内服务器没有备案域名）。

## 未做事项

- 用户登录和多设备同步（目前用 cookie 区分访客，清单跟着浏览器走）
- 券商对账单的更多格式（目前识别常见列名，未覆盖的列需要按模板调整）
- 当时的估值分位（需要历史估值数据）
- 更深入的模式统计（例如"每次追涨之后 10 天的平均表现"），目前组合层面有总结、处置效应和过度交易
- 提醒推送（清单只在决策前检查里使用，没有主动提醒）
- 浏览器端自动化测试（目前是接口冒烟 + 人工走查）
- 演示视频

## 本地运行

需要 Node.js 24 及以上（用到内置的 `node:sqlite`）。

```bash
npm install
cp .env.example .env.local   # 填入扶摇、DeepSeek、iFinD 的 Key
npm run dev                  # http://localhost:3000
```

| 环境变量 | 说明 |
|---|---|
| `FUYAO_API_KEY` | 扶摇金融数据 API Key |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | DeepSeek，模型默认 `deepseek-flash` |
| `IFIND_MCP_URL` / `IFIND_MCP_AUTH` | iFinD MCP 综合服务的地址和 Authorization |
| `IFIND_QUOTA_LIMIT` | iFinD 调用上限（免费试用总共 2000 次），到了就只用扶摇 |
| `ADMIN_TOKEN` | 运维令牌，带上才能重新生成示例组合的复盘 |
| `DATA_DIR` | SQLite 数据目录，默认 `./data` |

## 部署

```bash
bash scripts/deploy.sh ubuntu@<服务器IP> :80 -i <私钥路径>
ADMIN_TOKEN=<与服务端一致> bash scripts/pregenerate.sh http://<服务器IP>   # 预热示例组合并生成复盘
node scripts/smoke.mjs http://<服务器IP>
```

Docker 多阶段构建 + Caddy 反向代理（填域名时自动 HTTPS）。部署脚本会在国内服务器上配置 Docker 和 npm 镜像源。
